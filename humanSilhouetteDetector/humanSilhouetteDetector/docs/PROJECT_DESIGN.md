# Human Silhouette Detector — プロジェクト設計書

Web カメラ映像から人物を検出し、その輪郭（シルエット）をリアルタイムに認識・表示する
コンピュータビジョン アプリケーションの設計・開発documentです。
既存の `animalCnnAdd`（CNN 動物分類器）の後継として、ライブ映像の CV 処理へ拡張します。

開発モデルはウォーターフォール。本書は工程①〜⑤の確定成果物を統合したものです。
運用・保守の手引きは `OPERATIONS.md` を参照してください。

- 対象期間: 約 1〜2 ヶ月
- 言語 / 主要技術: Python 3.11+ / MediaPipe / OpenCV / Flask
- 提供形態: サーバ側で認識処理し、Flask により MJPEG でブラウザ配信

## 工程① 要件定義

### 1.1 プロジェクト概要
- 目的: Web カメラ映像から人の存在と輪郭をリアルタイムに認識するシステムを、商用利用可能な構成で構築する。
- 背景: 既存 CNN 動物分類器（画像→分類）の知見を、ライブ映像の CV 処理へ拡張する。

### 1.2 重要な技術的前提（用語の整理）
「ローカル LLM を使った画像認識」という当初要望を技術的に整理した結果、本件の主役は
LLM（言語モデル）ではなく **コンピュータビジョン（CV）** であると確定した。

| やりたいこと | 正しいタスク | 採用手法 |
|---|---|---|
| 人がいる/いないを把握 | 物体検出 | （包含） |
| 人の輪郭・シルエット抽出 | セグメンテーション | MediaPipe Pose（採用） |
| 姿勢を取る | 姿勢推定 | MediaPipe Pose（同時取得） |

顧客指示「人の輪郭まではわかるように」はセグメンテーションが本命であり、これを品質ラインとする。
LLM は本フェーズでは使用せず、将来 VLM（画像が読める言語モデル）併用の拡張余地として設計に残す。

### 1.3 スコープ（フェーズ分け）
**Phase 1（今回開発・対象内）**
- Web カメラ映像のリアルタイム取得・表示（CPU / iGPU 動作）
- 人物検出 + 輪郭セグメンテーションのオーバーレイ表示
- 処理後フレームは保存・送信せず破棄
- Flask によるブラウザ配信
- 全構成を商用組込可ライセンスに限定

**Phase 2（将来・対象外、ただし拡張点を設計）**
- VLM 併用（映像→状況の文章説明）
- サーバへの映像 / 顔データ転送・保存

**対象外（スコープ外と明記）**
- 個人を特定する顔認証・人物識別
- 複数カメラの同時管理

### 1.4 機能要件（FR）
| ID | 要件 | 優先度 |
|---|---|---|
| FR-01 | Web カメラ映像をリアルタイム取得・表示する | 必須 |
| FR-02 | フレーム内の人物を検出する | 必須 |
| FR-03 | 検出した人物の輪郭を抽出し映像に重ねて表示する | 必須（品質ライン） |
| FR-04 | 検出人数を画面に表示する（ON/OFF 切替可） | 推奨 |
| FR-06 | 入力 / 認識 / 出力を疎結合な層として実装する | 必須（設計要件） |
| FR-07 | 出力層を将来「転送 / 保存」に差替可能な I/F とする | 必須（拡張点） |
| FR-08 | 認識結果を Flask 経由でブラウザにリアルタイム配信する | 必須 |
| FR-09 | ブラウザで映像・人数・FPS を表示する | 必須 |

### 1.5 非機能要件（NFR）
| 区分 | 要件 |
|---|---|
| 性能 | CPU 環境で実用 FPS（目標 10fps 以上）。iGPU があれば活用可能 |
| 保守性 | 言語は Python（市場標準の AI 言語）。モデルは定番の MediaPipe |
| ライセンス / 法令 | 製品組込前提。Apache 2.0 / MIT / BSD 等の寛容ライセンスのみ採用 |
| プライバシー | v1 は即破棄。将来の保存 / 転送は同意・保持期間・暗号化・アクセス制御を有効化できる設計とし、実装前に法務確認をゲートとする |
| 移植性 | Win / Mac / Linux で動作。`requirements.txt` で再現 |

> 法務・プライバシー注記: 人を撮影・認識するシステムは個人情報保護法・肖像権等に関わる。
> 本書はエンジニアリング観点の整理であり、最終的な法的判断は顧客の法務確認を要する。

## 工程② 基本設計

### 2.1 設計方針
3 層レイヤアーキテクチャを採用し、各層を抽象基底クラス（インターフェース）で疎結合にする。
これにより認識ロジックの差し替え（CV → VLM 追加）や出力先の差し替え（破棄 → 転送）を、
他層に影響を与えず実施できる。

### 2.2 レイヤ責務
| 層 | 責務 | 入力 | 出力 |
|---|---|---|---|
| 制御層 (Pipeline) | 各層の生成・連携・ループ制御 | 設定値 | — |
| 入力層 (Input) | カメラからのフレーム取得を抽象化 | デバイス指定 | 1 フレーム画像 |
| 認識層 (Recognition) | 人物検出・輪郭・人数算出 | 1 フレーム画像 | 認識結果 |
| 出力層 (Output) | 結果の描画・破棄（将来は転送） | フレーム + 認識結果 | 画面表示 |

### 2.3 採用モデル選定
**採用: MediaPipe Pose Landmarker（Tasks API / `tasks-vision`）**

- ランドマーク（33 点）検出に加え、オプションのセグメンテーションマスクで輪郭抽出が可能。
  1 モデルで輪郭抽出（FR-03）・人数算出（FR-04）を両取りできる。
- ライセンスは Apache 2.0 系で商用組込可。
- CPU 動作し、必要に応じ GPU delegate で iGPU 活用も可能。
- 現行の Tasks API が正系であり、旧 `mediapipe.solutions` はレガシー。保守性のため新 API を採用。

**比較・不採用**
| 候補 | 判定 | 理由 |
|---|---|---|
| Image Segmenter (SelfieSegmenter) | 次点 | 自撮り想定で人数算出が弱い |
| YOLOv8 / v11-seg | 不採用 | AGPL-3.0 で商用組込に有償ライセンス必須 |

### 2.4 配信方式
**MJPEG ストリーミング（multipart/x-mixed-replace）** を採用。サーバが 1 フレームずつ JPEG 化し、
HTTP レスポンスを切らずに連続送信する。ブラウザは `<img>` タグで受ける。実装が枯れており軽量・高保守。
WebSocket は要件に対し過剰のため不採用（将来の双方向制御時の候補として保留）。

### 2.5 並行処理方針
カメラ取得・認識（重い処理）を Flask の配信スレッドから分離する。背景スレッド（生産者）が
最新フレームを保持し、配信側（消費者）はそれを読み出す **生産者・消費者パターン** を採る。
共有バッファは Lock で保護する。

### 2.6 配信トポロジ
```
[Webカメラ] → [認識処理(MediaPipe)] → [Flask配信(MJPEG)] → [ブラウザ表示]
              ←―――――― すべてサーバ側 ――――――→
```
カメラはサーバ側に接続され、認識もサーバ側で完結。ブラウザは配信映像を表示するのみ。

### 2.7 将来拡張点
| 拡張点 | 差し込む層 | 準備 |
|---|---|---|
| VLM 併用 | 認識層 | `RecognizerBase` 実装を追加。商用組込可の VLM を別途精査 |
| サーバ転送 / 保存 | 出力層 | `OutputHandlerBase` 実装を追加。同意・保持期間・暗号化・アクセス制御を前提 |

## 工程③ 詳細設計

### 3.1 データ構造
| 構造 | フィールド | 説明 |
|---|---|---|
| `Frame` | image (ndarray BGR) | OpenCV 画像 1 枚 |
| `RecognitionResult` | masks / person_count / landmarks | マスク・人数・33 点 |
| `Config` | （3.2 参照） | 設定値 |

認識層の出力は MediaPipe 固有型に依存せず素の numpy 配列に変換して保持し、出力層を疎結合に保つ。

### 3.2 設定初期値（テストで調整）
| キー | 初期値 | 根拠 |
|---|---|---|
| camera_index | 0 | 既定カメラ |
| frame_width / height | 640 / 480 | CPU 性能基準 |
| model_path | pose_landmarker_lite.task | CPU 速度優先 |
| num_poses | 2 | 控えめな初期値 |
| min_pose_detection_confidence | 0.5 | 標準 |
| output_segmentation_masks | True | 輪郭抽出に必須 |
| mask_threshold | 0.5 | マスク二値化しきい値 |
| jpeg_quality | 80 | 画質と帯域の妥協点 |
| show_person_count | True | 人数表示 ON/OFF |

### 3.3 認識モード
背景スレッドが 1 枚取得 → 1 枚処理を同期的に回す設計に整合させ、`VIDEO` モード
（`detect_for_video`）を採用（CR-02）。非同期コールバックの `LIVE_STREAM` より単純で堅牢。

### 3.4 モジュール処理手順（要点）
- **FrameSource**: `VideoCapture` を開き、`read()` で 1 フレーム返却。開けなければ例外。
- **CameraWorker（生産者）**: ループで 取得 → 認識 → 描画 → JPEG 化 → Lock 下で最新を保持。
  カメラ不可時はプレースホルダ配信に切替（致命的にしない）。認識例外はフレーム単位でスキップ。
- **Recognizer**: BGR→RGB 変換、`detect_for_video` で結果取得、masks を numpy 化して返却。
- **draw_overlay（品質ライン）**: 全マスク統合 → 二値化 → `findContours` → 半透明塗り
  （`addWeighted`）+ 輪郭線（`drawContours`）→ 人数 / FPS を縁取りテキスト表示。
- **Flask app（消費者）**: 起動時に worker 開始。`/video_feed` が最新 JPEG を multipart で配信。

### 3.5 例外処理方針
| 事象 | 挙動 |
|---|---|
| カメラ開けない | プレースホルダ配信、アプリは継続 |
| モデル読込失敗 | 起動時に致命エラーで停止（早期検知） |
| 人物未検出 | 素のフレームを配信（正常） |
| ブラウザ切断 | 配信ジェネレータ終了、背景スレッドは継続 |
| 認識中例外 | ログ後フレームスキップ、直前の正常フレーム保持 |

├─ models/                        # .task モデル配置先

├─ THIRD_PARTY_LICENSES.md        # 依存ライセンス一覧

## 工程⑤ テスト

機能 / 性能 / 異常系 / 商用・プライバシーの 4 分類で、各テストケースを要件 ID に紐づけて
検証する（トレーサビリティ）。判定は OK / NG / 保留。NG は課題管理票に起票し再テストする。
テスト仕様書 兼 結果報告書の本体は `TEST_PLAN.md` を参照。

### 主な観点
- 機能: 映像表示 / 人物検出 / 輪郭表示（品質ライン）/ 人数表示 ON-OFF / 複数人
- 性能: CPU で目標 10fps / iGPU 加速 / 負荷時に固まらない / 解像度調整で改善
- 異常系: カメラ未接続 / ブラウザ切断 / モデル不在 / 人物なし
- 商用・プライバシー: 非保存・非送信の確認 / ライセンス棚卸し（AGPL 混入なし）

### トレーサビリティ
全 FR / NFR が `TEST_PLAN.md` のいずれかのテストケースで覆われていることを確認済み。
